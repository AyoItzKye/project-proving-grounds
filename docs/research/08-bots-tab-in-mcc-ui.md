# 08 - A "Bots" tab in the MCC custom game lobby

Date: 2026-10-22. MCC build on this PC: Steam `2025.08.16.178512.1-Release` (file version 1.3528), anti-cheat-off mode only.
Goal: a fifth tile "BOTS" next to MAP / GAME TYPE / OPTIONS / START on the "HALO: CE CUSTOM GAME" screen, with a Spartan-style icon (for example active camo), opening bot settings (count, teams, difficulty).

LOCAL = verified read-only on this PC's install (`<Steam library>\steamapps\common\Halo The Master Chief Collection`). Nothing in the install was modified.

## 0. Short answer

- **The custom game lobby is not UMG.** It is a Scaleform GFx (Flash, ActionScript 3) movie, `Data\UI\Screens\multiplayercustomgame.gfx`, from MCC's legacy "UUI" front end. UE4 only hosts it: UUI draws into a render target that a UMG widget (`WBP_UUIRendering`) puts on screen. The newer PC-only screens (settings, store, customization, PGCR, custom games browser, roster) are UMG. (LOCAL, section 1.)
- So pak/UMG modding cannot add a tile to this screen. A "real" tile means editing the Scaleform movie's AS3 and also hooking the C++ side that drives it.
- **Recommended:** option (c), a Dear ImGui panel drawn by `botcore.dll` on the D3D11 swapchain, shown only while the CE custom game lobby is open, laid out as a fifth tile to the right of START and styled to match. Two other MCC mods (AlphaRing, HaloCheckpointManager) already ship this pattern. Optional later upgrade: option (d1), a native fifth tile in the Scaleform movie.

No public writeup found that documents MCC's Scaleform layer; this section rests on the local evidence above. No sign of Coherent, CEF-as-UI, Noesis or Ultralight in the exe (LOCAL string scan; the "cef" hits were substrings of other words).

### 1.3 UE4 version

- repak's table maps pak version 7 (EncryptionKeyGuid) to **UE 4.21** ([repak compatibility table](https://github.com/trumank/repak)).
- A Gildor forum reply (Dec 2019) says "The launcher/UI use UE4 4.21"; the original post says the engine version string was scrubbed from the exe and pak ([Gildor forum thread](https://www.gildor.org/smf/index.php/topic,6686.0.html)). LOCAL confirms no `++UE4+Release-4.xx` string in the exe.
- LOCAL: loose `MCC\Content\Splash\Splash.uasset` has `FileVersionUE4 = 517`, legacy version -7. Mapping 517 to a minor release is UNVERIFIED, but it fits the 4.21/4.22 window.
- Conclusion: UE 4.21 (high confidence), with Microsoft/Splash Damage engine changes.

## 3. Options, ranked

### Rank 1 (recommended): (c) ImGui overlay "BOTS" tile drawn by botcore.dll

What it is: hook `IDXGISwapChain::Present` (HCM pattern), draw a tile-shaped ImGui button to the right of START only while the CE custom game lobby is open, and open a bot settings panel (count, teams, difficulty) when it is clicked.

- Feasibility: high. Proven in MCC by AlphaRing and HCM (both ImGui on D3D11). No game files touched.
- Effort: low to medium. Present hook + ImGui DX11 backend (about 300 lines, mostly copied from HCM's MIT code), a tile renderer, a settings panel, and screen detection (section 5).
- Matching the look: draw a dark translucent rectangle with a thin light-blue frame and a highlight bar, like the stock tiles (the lobby uses `ButtonHighlightBacking`, `WideBoxSelected`, `FX_EdgeEffect` art). Use a free font close to "Blender Halo" (the real font is commercial, so do not ship it). Place the tile using a size relative to the window, with a calibration offset in `botcore.ini`, because the Scaleform stage scales with resolution and aspect.
- Input: mouse works directly (ImGui hit-test). For controller and keyboard, use one dedicated button while the lobby is open (for example View/Back or `B` key, shown as a prompt under the tile), and while the panel is open, swallow input so the lobby below does not react (HCM `BlockPlayerCharacterInput` / `FreeMCCCursor` patterns). The tile is not part of MCC's own focus chain, so the D-pad will not move onto it. That is the main weakness.
- Breakage on MCC updates: low. The Present hook does not depend on the build. Only the screen-detection offsets or signatures need refreshing per build (they already need it for bots).
- Needs: ImGui (MIT), MinHook or similar, HCM's D3D11 hook as reference, the detection signal from section 5.

### Rank 2 (optional upgrade): (d1) Native fifth tile by editing the Scaleform movie

What it is: copy `multiplayercustomgame.gfx`, add a fifth tab (clone the `OPTIONS` tab clip, new label "BOTS", new tooltip, art set by texture name) in FFDec, and make its accept action call `ExternalInterface.call("Bots...")` or `fscommand(...)`. `botcore.dll` hooks the GFx external-interface / FSCommand handler, catches that call, and opens the bot panel (ImGui, or a second edited movie).

- Feasibility: medium. The AS3 hard-codes four tabs (`mTabHelpBar0..3`, `TabHelpKnob0..3`, index-based tab logic), so tab count, navigation wrap, and layout code must all change. The C++ side owns tab focus; whether it accepts a fifth index without crashing is UNVERIFIED.
- Effort: high. AS3 bytecode editing, plus RE of the C++ to GFx bridge (Scaleform symbols are present as log strings only; no RTTI; no public Scaleform SDK headers for this version).
- Breakage: medium to high. Any MCC patch that touches the file or the bridge breaks it; Steam "verify files" restores the stock file. Does MCC check `.gfx` integrity with EAC off? UNVERIFIED (none seen).
- Licensing: shipping a modified Microsoft file is a redistribution of game content. Ship a binary patch that the user applies locally to their own copy instead.
- Payoff: a real tile with native focus, sounds, and controller navigation.

Variant (d2): leave the file alone and inject the fifth tab at runtime by calling into the live GFx movie (`attachMovie`, `SetVariable`, `Invoke`) from our DLL. Same RE cost as (d1) plus finding the GFx Movie object; no file edits. Effort very high. UNVERIFIED that the needed GFx API entry points are reachable.

### Rank 3: (b) UE4SS or our DLL creating a UMG widget at runtime

- The lobby is not UMG, so a UMG widget can only sit **on top** of the UUI render target (higher Z-order in the viewport), which is no better than (c) visually.
- Building the widget tree from code with no cooked `WBP_` asset is slow work. Cooking our own `WBP_BotsTile` needs a UE 4.21 editor and a mountable pak. With pak v7, an unencrypted index and no `.sig` files, a `_P` patch pak may load, but this is UNVERIFIED for MCC (Microsoft may have changed pak mounting).
- UE4SS itself is unproven on MCC (section 2), needs AOB fixes, and adds a second injected runtime next to `botcore.dll`.
- Input: UMG focus vs UUI input (`UUIInputAction`) routing is unknown; risk of double input. UNVERIFIED.
- Effort: medium-high. Breakage: medium (AOBs, engine offsets per build).
- Useful side benefit: UE4SS's object dumper and `RegisterHook` would help find the screen-change UFunctions in section 5. Use it as a one-off RE tool, not as the shipping path.

### Rank 4: (a) Pak/asset modding to add a real tile

- Not workable for this screen: the CE custom game lobby is in a loose Scaleform file, not in the pak. Pak edits can only touch UMG screens (main menu, settings, browser). Adding an entry to `WBP_MainMenu` / `DT_MainMenuData` through a patch pak is plausible but would put "Bots" in the main menu, not the lobby. It needs the 4.21 editor and cooking, and every MCC patch is a 10.9 GB pak replacement. UNVERIFIED that MCC mounts extra paks.

### Other ideas

- Hijack an existing control: when the user opens OPTIONS on this screen, our panel appears beside the stock options list as a "Bots" section. This uses the same detection as (c) plus "options sub-screen open"; it feels more built-in and needs no new tile.
- Button-bar prompt only: draw "[View] Bots" in the bottom button bar area (UMG `WBP_MCCButtonBar` region). Cheapest and least intrusive; pairs well with (c).

## 4. Active camo / Spartan icon art

Where it is (LOCAL):
- UUI texture pack `Data\UI\texturepacks\mainmenutexturepack.perm.bin` (index) + `.temp.bin` (pixels, 81.7 MB) contains `LOADOUT_ARMOR_ABILITY_ACTIVECAMO` and a large variant ending `..._ACTIVECAMO` (the Reach armor ability icon), next to `..._JETPACK`, `..._HOLOGRAM`, `..._THRUSTER`, `..._REGENFIELD`, `..._AUTOSENTRY`.
- `globaluitexturepack.perm.bin` contains a texture named **`ADD_BOT`**, sitting between `SAVE_EXIT`, `SAVE_RESTART`, `NEXT_GAME` (button-prompt icons). Its look and use are UNVERIFIED; it may be a leftover from Xbox One/Forge UI. Worth extracting and looking at first.
- Pak `MCC/Content/UI/Shared/Textures/Icons/` has 32 UMG icons (settings cog, difficulty skulls, season icons, `T_PlayerID`, `T_Customization`); no camo icon.
- Halo CE itself has no camo HUD icon. HCEEK tags have only `rasterizer/active camouflage distortion.bitmap` (LOCAL). The HREK tags (`HREK.7z`, not extracted) should hold Reach HUD ability bitmaps (UNVERIFIED).

Can it be extracted:
- UUI texture packs: format undocumented; the `.perm.bin` header shows plaintext names followed by size/format fields (LOCAL hex view), so a small parser is possible. No public tool found ([search](https://www.moddb.com/games/halo-combat-evolved/downloads/reclaimer-1-5-245)). UNVERIFIED.
- Pak UMG textures: FModel/UModel export to PNG (sections 1.2, 2).
- Editing kit bitmaps: `tool.exe` / Foundation export (official route).
- Best of all for option (d1): no extraction needed. The Scaleform movie loads art **by texture name**, so the BOTS tile can reference `LOADOUT_ARMOR_ABILITY_ACTIVECAMO` (or `ADD_BOT`) already on the user's disk.

Microsoft Game Content Usage Rules ([xbox.com/developers/rules](https://www.xbox.com/en-US/developers/rules), last updated January 2015):
- Grants a personal, noncommercial, revocable license to use Game Content and make derivative works. Free distribution is allowed; no selling, ads, paid or subscription hosting.
- If shared, include: "Halo: The Master Chief Collection © Microsoft Corporation. [Mod name] was created under Microsoft's "Game Content Usage Rules" using assets from Halo: The Master Chief Collection, and it is not endorsed by or affiliated with Microsoft." plus a link to the rules.
- **** Extracting an icon by reverse engineering an undocumented texture pack, and the mod itself, are in tension with this clause. The rules are written for videos and fan works; how they apply to code mods is a gray area (UNVERIFIED legal reading, not legal advice).
- Lowest-risk path: **do not ship Microsoft art.** Either (1) draw our own original Spartan-style icon (helmet silhouette with a camo shimmer) for the overlay, or (2) load the stock icon at runtime from the user's own install, without redistributing it.

## 5. How botcore.dll can know the CE custom game lobby is open

Use layered signals, cheapest first:

1. **In menus vs in game (known offsets, 1.3528 Steam):** `menuindicator` = byte at `MCC-Win64-Shipping.exe + 0x4000B8C + 0x11` (0 = main menu, 1 = in game). `loadindicator` = `+0x4000B8C`, `pauseindicator` = `+0xB`, `pgcrindicator` = `+0xC`. `gameindicator` = byte at `[exe + 0x4001658] + 0`, which says which title is selected ([MCC_autosplitter.asl](https://github.com/Burnt-o/MCC_autosplitter/blob/HEAD/MCC_autosplitter.asl); same `menuIndicator` entry with the note "0 when in MainMenu, 1 when in-game" in HCM `InternalPointerData.xml`, LOCAL). Gate: show nothing unless `menuindicator == 0`.
2. **Which UUI screen is open (needs RE, recommended):** in Ghidra, follow xrefs from `UIScreenMultiplayerCustomGame_Data`, `UIScreenManager`, `UIScreenFactory`, and the `%s.gfx` / `Failed to bind SWF file` path to find the screen-stack push/pop. Hook push/pop, or read the top-of-stack screen ID each frame. This gives an exact "custom game lobby is on top" flag and also tells us when a sub-screen (map picker, options) covers it. UNVERIFIED until found.
3. **Scaleform call sniffing (good fallback):** hook the GFx movie `Invoke` path. When C++ calls `setScreenTitle` / `showChooseMap` / `setStartInfo` on the `multiplayercustomgame` movie, the lobby is live. This also gives the selected map and game type for free. UNVERIFIED entry points.
4. **UE4 side:** hook `UObject::ProcessEvent` (or UE4SS `RegisterHook`) for `OnUUIContextChanged` / `UpdateUUIData`, if these are reflected UFunctions. Log names once to find which fires on entering the lobby. UNVERIFIED.
5. **File-open hint (cheap, weak):** a `CreateFileW` hook that sees `Data\UI\Screens\multiplayercustomgame.gfx` opened. Scaleform may cache the movie after the first load, so this alone cannot detect re-entry. UNVERIFIED.
6. **Last resort:** template-match the "CUSTOM GAME" header and the four tiles in a downscaled frame grabbed in our Present hook. Works across builds but breaks with language or resolution changes.

Title check: the lobby header reads "HALO: CE CUSTOM GAME"; combine signal 2 or 3 with `gameindicator` so the BOTS tile shows only for CE until other titles are supported.

## 6. Proposed plan

1. Add the Present hook + ImGui to `botcore.dll` (copy HCM's MIT `D3D11Hook` approach; credit it).
2. Detection v1: `menuindicator == 0` + Scaleform or screen-manager hook (one-day Ghidra task on the exe), with the file-open hint for logging.
3. Draw the BOTS tile right of START with our own icon; a settings panel with count (1 to 15), team (auto/red/blue/FFA), difficulty (Easy/Normal/Heroic/Legendary, matching the stock difficulty icons in style only); save to `botcore.ini`; feed the existing bot launcher.
4. Calibrate the tile position from screenshots at 1080p, 1440p, ultrawide (use `tools/mcc_nav.py` captures).
5. Later, if the player wants a native tile: prototype (d1) on a copy of the `.gfx`, applied as a local patch with a restore button.
