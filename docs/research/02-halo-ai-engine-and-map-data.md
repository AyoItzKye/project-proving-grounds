# 02 - Halo AI engine and multiplayer map data (per game)

Research track: how the Halo AI engine works in each MCC game, and what a multiplayer (MP) map needs before AI bots can work on it.
Date: 2026-10-21. Scope: Halo CE (H1A / HEK), Halo 2 (H2EK), Halo 3 (H3EK), ODST (H3ODSTEK), Reach (HREK), Halo 4 (H4EK), MCC PC, offline / anti-cheat off.

Conventions:
- Every non-obvious claim has a source URL. "UNVERIFIED" marks things that are inference, single-anecdote, or not found in any source.
- "c20" = The Reclaimers Library, https://c20.reclaimers.net
- "Assembly plugin" = the community tag layout files in the XboxChaos Assembly repo (https://github.com/XboxChaos/Assembly/tree/master/src/Assembly/Plugins), used here only to list tag field names that c20 has not documented yet.

## 1. Pathfinding

### 1.1 Halo CE (H1A / HEK)
- Pathfinding data lives in the BSP (`scenario_structure_bsp`): "This data is generated automatically during BSP compilation and is retained even in when the BSP is compiled into multiplayer maps." https://c20.reclaimers.net/h1/tags/scenario_structure_bsp/
- The BSP has a `pathfinding surfaces` block (one entry per collision surface, value 0 = not walkable e.g. too steep, 64 otherwise) and a `pathfinding edges` block. Same page.
- Navigation uses the precomputed BSP data plus object "pathfinding spheres" (projected to discs on the ground plane). A smoothed node path is built (believed to be A*); dynamic obstacles cause local detours without a full repath. Max path distance 3276.7 world units (Blood Gulch bases are about 100 apart). "Halo 1 does not support pathfinding in moveable reference frames." https://c20.reclaimers.net/h1/engine/ai/
- Firing positions "are not pathfinding nodes, but rather a pathfinding destination." Same page.
- Consequence for us: every stock CE MP map already has walkable-surface data. We only need to add encounters, squads and firing positions in Sapien. No hint system equivalent to H2+ was found for CE (UNVERIFIED whether CE has any user hints).
- AI placed on scenery (not BSP) may stand in place unable to move (Custom Edition forum anecdote). https://halomaps.haloman30.com/index.cfm%3Fpage=topic&topicID=35133

### 1.2 Halo 2 (H2EK)
- "Halo 2 uses an automatically generated pathfinding mesh using the collision mesh of the BSP as the base." It adds scenery and instance geometry collision, removes faces steeper than 45 degrees, and optimises into convex sectors. "It will fail if the BSP has any open edges." https://c20.reclaimers.net/h2/engine/pathfinding/
- Map makers have "limited control": the generator settings are mostly not user facing. Same page.
- Scenery pathfinding policies: Static (stitched into mesh, AI can walk on it), Dynamic (device machines), and others. Same page.
- Hints: many are autogenerated; user hints placed in Sapien (AI > Pathfinding data > Hints). Render with `ai_render_user_hints 1` / `ai_render_hints 1`; sectors with `ai_render_sectors 1`. Autogenerated jump hints are based on user jump hints and change when pathfinding is regenerated. Same page.
- Object hints (crates): `hint_bunker`, `hint_corner_left/right`, `hint_vault_crouch`, `hint_mount_crouch`, `hint_hoist_crouch`, `hint_hoist_stand`. Same page.
- Long narrow sectors make AI move oddly; fix with a correctly sized cookie cutter, but do not overuse. Same page.
- Bungie's own description: ground movement on a navmesh, airborne on a waypoint network, path smoothing, hints for jumping and climbing. https://web.eecs.umich.edu/~sugih/courses/eecs494/fall06/lectures/lecture18-halo2.pdf
- Exact tool step that generates the H2 mesh (Tool on import vs Sapien) is UNVERIFIED.

### 1.3 Halo 3 / ODST / Reach (H3EK family)
- AI use pre-calculated pathfinding plus placed firing positions as goals. Small gaps players ignore can break AI transitions, needing a jump hint. "Levels much be entirely sealed: like a balloon, any holes in this balloon will cause pathfinding failure." https://c20.reclaimers.net/h3/engine/pathfinding/
- Workflow: create zone, place firing positions, group them into areas (Ctrl+N), then "(re)generate pathfinding in Sapien using the 'Generate all pathfinding data' button under the 'Scenarios' tab". Same page.
- Object pathfinding policies: Default, Dynamic (crates, machines), Cut-out (dead zone), Static (stitched in), None. Vehicles and bipeds use dynamic pathfinding. Same page.
- Hint types (Sapien, render with `ai_render_hints 1`), all with `bidirectional` flag:
  - Jump hint: drawn vectors for jumps over obstacles or drops. Flags: `magic lift` (unknown), `vehicle only` (unknown), `railing` (vault). Same page.
  - Climb hint: vertical two-point path; AI use hoist step / crouch / stand animations depending on height. Same page.
  - Well hint, Flood hint: wall/ceiling movement for Flood and drones; need `climb` and `perch_wall_*` animation modes. Same page.
  - Flight hint: path for flying AI without firing positions. Same page.
  - Cookie cutter: box that blocks all pathfinding; overshoot the geometry slightly. Same page.
  - Giant hints (sector + rail): Scarab movement. Same page.
  - Object hints: vault / mount / hoist, defined by render_model markers. Same page.
- Debug icons over AI heads: green = no firing positions (no zone/objective); yellow = too few firing positions or cannot pathfind to them; red = missing idle/alert style or animation modes. https://c20.reclaimers.net/h3/engine/pathfinding/ and https://c20.reclaimers.net/h3/engine/ai/
- Scenario blocks that hold the data (Assembly layouts): H3 has `Jump Hints`, `Climb Hints`, `Well Hints`, `Flight Hints`, `Cookie Cutters`, `Giant Hints`, `Flood Hints`; ODST and Reach group user hints under `AI Pathfinding Data`. https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo3MCC/scnr.xml , https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/ReachMCC/scnr.xml
- Reach Forge AI mod author: AI standing on Forge objects; teleporting reveals a "huge pathfinding box" region limit. Search summary of https://catalogue.smods.ru/?p=189035 and https://steamcommunity.com/sharedfiles/filedetails/changelog/2899383598. So Forge-placed geometry is not in the navmesh (consistent with policy "None"/dynamic). UNVERIFIED for H3 Forge objects.

### 1.4 Halo 4
- H4 scenarios still have zones, areas, firing positions and pathfinding references (Assembly layout). https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo4MCC/scnr.xml
- How H4 pathfinding is generated and which hints exist: UNVERIFIED (c20 has no H4 AI pages yet).

### 1.5 Man cannons, teleporters, lifts (all games)
- No source documents AI using MP teleporters or man cannons natively. UNVERIFIED but likely: the navmesh has no concept of teleporter links, so AI will never route through them.
- H3 jump hints have an undocumented `magic lift` flag (possible gravity lift support, UNVERIFIED). https://c20.reclaimers.net/h3/engine/pathfinding/
- Practical workaround (design, not sourced): trigger volume at entry + script `object_teleport` to exit flag (CE has `object_teleport` https://c20.reclaimers.net/h1/scripting/), and treat each side of a teleporter as separate zones/areas in the director.

## 2. AI placement data and the objectives system

### 2.1 Halo CE
- AI are grouped into encounters that own firing positions; subsets are made available depending on encounter state (losing, winning, casualties). https://c20.reclaimers.net/h1/engine/ai/
- Scenario blocks: Encounters (HEK max 128), each with Squads (max 64), Platoons, Firing Positions (max 512), Starting Locations. Squad fields: initial state (none, guarding, searching, fleeing...), return state, "maneuver to squad", firing-position letter sets for attacking / attacking search / attacking guard. "Squads need at least one valid starting position." Encounter team index can be "default by unit". https://c20.reclaimers.net/h1/tags/scenario/
- `ai_follow_*` makes AI move to firing positions "with the same letter label that their target is near." https://c20.reclaimers.net/h1/engine/ai/
- Encounter team 0 = red, 1 = blue in MP (forum claim, UNVERIFIED in docs). Search summary of https://halomaps.haloman30.com/index.cfm%3Fpage=topic&topicID=26792
- CTF mapping idea for CE: one encounter per team; squads per role (defend, attack, midfield) with distinct firing-position letters; the director script uses `ai_migrate` to move actors between role squads.

### 2.2 Halo 2
- Scenario blocks: Squad Groups, Squads, Starting Locations, Zones, Firing Positions, Areas, Flight Hints, Mission Scenes, Orders (Primary/Secondary Area Set, Secondary Set Trigger, Order Endings), Triggers, AI Triggers. https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo2MCC/scnr.xml
- Script: `ai_set_orders <ai> <ai_orders>` "Use the zone_name/order_name format". https://c20.reclaimers.net/h2/engine/scripting/

### 2.3 Halo 3, ODST, Reach, H4 (objectives and tasks)
- Organization: squads -> fireteams -> starting positions; squads can be grouped into squad groups; squads are the main gameplay and script entity. https://c20.reclaimers.net/h3/engine/ai/
- Zones are top level; objectives reference a zone; areas (inside zones) hold firing positions; tasks reference areas. Areas can be vehicle-only or turret-deployment. Firing positions have posture flags corner_left, corner_right, bunker. https://c20.reclaimers.net/h3/engine/pathfinding/
- Objective system: priority based, squads always try to fill a higher priority task; "squads cannot be split up to fill different tasks and will only enter a task that can fit the entire squad." https://c20.reclaimers.net/h3/h3-ek/h3-sapien/objectives/
- Task flags: LATCH ON, LATCH OFF, Gate (parent only), Single Use, Suppress Combat, Active Camo, Blind, Deaf, Braindead, Magic Player Sight (see player through walls), DISABLE. Inhibit groups: Cover, Retreat, Vehicles, Grenades, Berserk, Equipment. Per-difficulty disable. Same page.
- Task properties: movement (walk/run/crouch), follow (player / squad + radius), entry script, command script, exhaustion script, squad group filter. Same page.
- Conditions: activation script (compiled), lifetime count, filter, capacity, max body count, style (normal / bunkering / assaulting), min strength. Same page.
- Area roles inside a task: Normal, Core (leader), Search, Goal ("AI will actively try to reach this area at all costs"). Same page.
- Bungie design intent: designers state tasks (territory, vehicles to man, targets), squads assign themselves; tasks are a priority tree with activation conditions and NPC caps. Damian Isla, "Building a Better Battle" (GDC 2008): https://web.cs.wpi.edu/~rich/courses/imgd4000-d10/lectures/halo3.pdf
- Info is shared within a squad and within a task, but "not passed between squads, even if they are right next to each other." https://c20.reclaimers.net/h3/engine/ai/
- ODST Firefight shows the full pattern for respawning AI with scripts: wave squads, squad groups, objectives reset by `global_survival` each wave, spawn formations. https://c20.reclaimers.net/h3odst/guides/firefight/firefight-setup/

### 2.4 Mapping to CTF roles (design proposal, not sourced)
- One objective per team (e.g. `obj_red`, `obj_blue`). Child tasks with priorities: `defend_flag` (core area at own flag room, capacity N), `attack_enemy_flag` (goal area at enemy flag), `escort_carrier` (follow squad), `midfield`, `fallback`. Activation conditions are HaloScript booleans the director sets (globals like `g_red_flag_taken`).
- Director reassigns with `ai_set_task <squad> <objective> <task>` or by latching conditions with `ai_set_task_condition`. Since squads are atomic, make each bot its own squad so tasks can be filled one bot at a time.

## 3. Character, style and behavior settings

### 3.1 Halo CE (actor + actor_variant)
- actor tag: behaviour flags such as swarm, crouch rules, "panic when surprised", "dive off ledges", "pathfinding ignores danger"; perception (max vision distance, central / max / peripheral vision angles, hearing distance, combat / guard / non-combat perception time); cover and retreat (dive into cover chance, retreat time, hide / attack / pursue shield fraction, surprise distance). https://c20.reclaimers.net/h1/tags/actor/
- Hard-coded behaviours exist (Grunts flee when their Elite dies). 14 actions: none, sleep, alert, fight, flee, uncover, guard, search, wait, vehicle, charge, obey, converse, avoid. https://c20.reclaimers.net/h1/engine/ai/
- actor_variant (weapons and aim): weapon reference, rate of fire (0 = hold trigger), projectile error, first burst delay, target tracking (0 to 1), target leading (0 to 1), weapon damage modifier, burst origin radius / angle, burst return length / angle, burst duration, burst separation, burst angular velocity, plus multipliers for new-target, moving and berserk states. Flags: "can shoot while flying" (also while jumping or falling), "has unlimited grenades", "prefer passenger seat". https://c20.reclaimers.net/h1/tags/actor_variant/
- Burst model: each burst starts at a random point left/right of the target and walks back toward it. Same page.

### 3.2 Halo 2
- character tag blocks: General, Vitality, Placement, Perception, Look, Movement, Swarm, Ready, Engage, Charge, Evasion, Cover, Retreat, Search, Pre-Search, Idle, Vocalization, Boarding, Boss, Weapons, Firing Patterns, Grenades, Vehicle. Movement has jump height enum (None, Down, Step, Crouch, Stand, Storey, Tower, Infinite) and vault/mount/hoist movement hints. https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo2MCC/char.xml

### 3.3 Halo 3 / ODST (character + style)
- Two mandatory tags: style = which behaviours are allowed at all; character = when / how long ("the brain"). https://c20.reclaimers.net/h3/engine/ai/
- Style flags include equipment, grenade_impulse, anti_vehicle_grenade, flank, melee_charge, melee_leaping_charge, shield_depleted_berserk, last_man_berserk, kamikaze, plus Presearch, Search, Retreat, Vehicle, Swarm groups. https://c20.reclaimers.net/h3/tags/style/
- Character blocks (Assembly): Perception (vision distance and angles, hearing, perception time, "can see in darkness"), Look, Movement, Flocking, Swarm, Ready, Engage, Charge, Evasion (danger threshold, delay, chance, dive retreat chance), Cover, Retreat, Search, Pre-Search, Idle, Weapons (min/max/normal combat range, first burst delay, **Normal / Heroic / Legendary Accuracy Bounds and Time**, rate of fire, target tracking, target leading, burst geometry, projectile error, maximum error angle), Firing Patterns, Grenades (type, trajectory, chance, count, velocity), Vehicle, Equipment Use. Movement: "No Side-Step", "Allow Boosted Jump", "Cure Isolation Jump", "Jump Height", obstacle leap sizes, vault / mount / hoist hints. https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo3MCC/char.xml
- Perception is real: no wallhacks unless a task has Magic Player Sight; sound radius scales with hearing distance; squadmates share target locations; each AI tracks up to 20 props and 4 targets. https://c20.reclaimers.net/h3/engine/ai/
- Combat status ladder 0 to 9 (asleep ... dangerous). Scariness = biped scare + weapon scare vs target's. Accuracy and firing pattern reset after dodge, stun, hard ping or movement hint. Same page.
- Hard limitations that matter for PvP: AI cannot move while throwing grenades; cannot see through glass or shield walls; **do not consume ammo, so never reload magazine weapons**; cannot melee while moving; **cannot shoot or melee while jumping**; use biped melee damage, not weapon melee damage, unless the weapon flag "AIs use melee damage" is set. https://c20.reclaimers.net/h3/engine/ai/ and https://c20.reclaimers.net/h3/tags/object/item/weapon/
- Debug: `ai_render_all_actors`, `ai_render_behavior_stack`, `ai_render_targets`, `ai_render_shooting`, `ai_render_status_flags`, `ai_debug_emotions`. https://c20.reclaimers.net/h3/engine/ai/

### 3.4 Reach
- Character adds: Target, Emotion, Situational Danger, Interact, Firing Point Evaluator, Movement Sets, Throttle control, Kungfu, Bunker, Engineer, Inspect, Flying Movement, Stimuli Responses. Movement adds "Allow Jump to Firing Position", "Gain Elevation", "Use High Priority Pathfinding", **Armor Lock Chance, Grenade Stuck Armor Lock Chance, Armor Lock Safety / Maximum Duration, Cooldown**, Brace Grenade Chance, Maximum Leap Height. Equipment Use "Use When": Combat, Cover, Shield, Health, Uncover, Berserk, Investigate, Anti Vehicle; "Use How": Attach To Self, Throw At Enemy, Throw At Feet, Use On Self. Weapons has "Disallowed Weapons From Trading" (AI weapon trading). https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Reach/char.xml
- So Reach AI can be configured to use armor lock and equipment-style abilities. Whether AI can use Sprint, Jetpack, Evade, Hologram, Drop Shield as MP armor abilities through Equipment Use: UNVERIFIED. Elites use an evasive dive in campaign (Game Informer, https://gameinformer.com/b/news/archive/2010/07/20/halo-reach-armor-abilities.aspx ); active camo is used by enemy Elites/Brutes (https://www.halopedia.org/Armor_ability ).

### 3.5 Halo 4
- Character adds Hopping, Cover Evasion, Fight From Cover, Advance, Dynamic Task, Gravity Jump, Extreme Range Firing Pattern, same Armor Lock and Equipment Use fields as Reach. https://github.com/XboxChaos/Assembly/blob/master/src/Assembly/Plugins/Halo4/char.xml (non-MCC layout, field names assumed same in MCC, UNVERIFIED).

## 4. Multiplayer bipeds, objective items, scoring, teams, respawn

### 4.1 Can AI use MP bipeds?
- CE: yes in practice. "Halo AI v2" adds Red and Blue AI Spartans to five stock MP maps; AI start with the gametype weapon, can drive (poorly) and melee. Search summary of https://www.nexusmods.com/halocustomedition/mods/25 (page 403 on direct fetch).
- H3: the stock Chief has no AI set (Steam 2021 discussion, via search summary https://steamcommunity.com/app/976730/discussions/3/3275816470990289366 ). A community AI Spartan biped ported most animations "from the spartans_ai tag from Halo Reach", and the stock H3 Spartan skeleton "lacks a physics_control node", required for climbing / cover animations. https://nexusmods.com/halothemasterchiefcollection/mods/2397 (via search summary; direct fetch blocked by Cloudflare).
- H3 animation requirement: missing idle/alert style or animation modes gives a red debug triangle; wall movement needs `climb` / `perch_wall_*` modes; climb hints need hoist animations. https://c20.reclaimers.net/h3/engine/pathfinding/
- Reach: `spartans_ai` graph exists (above). DunkODST's "Spartan Team" Reach Workshop mod runs AI Spartans that defend generators; author replaced `melee_strike_dash` because bots spammed melee, and considered heat weapons to force reloads. https://steamcommunity.com/sharedfiles/filedetails/comments/3543102766 (via search summary).
- H2, ODST, H4 MP-biped AI: UNVERIFIED.

### 4.2 Can AI carry the flag / oddball?
- Flag and oddball are weapon tags. CE flags: "must be readied" (cannot switch away, dropped by trigger or grenade) and "doesn't count toward maximum" (auto pick up on walk-over). https://c20.reclaimers.net/h1/tags/object/item/weapon/
- H3: `multiplayer weapon type` enum marks objective items; flag "cannot be used by player" exists; "must be readied" "attempting to attack with weapon will force drop it." https://c20.reclaimers.net/h3/tags/object/item/weapon/
- No source confirms that stock AI will pick up or score with a CTF flag. Halo Infinite Forge bots reportedly "do not carry the Core objective" (r/forge anecdote, different engine). Search summary only. Treat as UNVERIFIED and a likely blocker. Script fallbacks: give the weapon directly to the AI unit (H3 has `unit_add_equipment`-style and weapon functions; exact one UNVERIFIED), or fake carrying with an attached object plus script-checked capture volumes.

### 4.3 Do AI kills count on the MP scoreboard?
- No source found for any game. UNVERIFIED and a key open question.
- Script-side score control exists only in H4: `adjust_player_score <player> <long>` and `adjust_team_score <mp_team> <long>`, "NETWORK SAFE: Host only". https://c20.reclaimers.net/h4/engine/scripting/
- H3 / ODST / Reach: `mp_game_won <mp_team>` can end the game for a team. https://c20.reclaimers.net/h3/engine/scripting/
- Reach: Megalo gametype scripts (ReachVariantTool) can hold custom score logic; whether Megalo events fire for AI-controlled bipeds is UNVERIFIED. https://github.com/DavidJCobb/ReachVariantEditor/releases
- CE pattern for counting AI deaths: track a unit, loop until its health is 0, add to a score global. Halomaps forum, via search summary https://halomaps.haloman30.com/index.cfm%3Fpage=topic&topicID=35115
- Killfeed entries for AI kills: UNVERIFIED for every game.

### 4.4 Team / allegiance mapping
- CE: `ai_allegiance <team> <team>`, `ai_set_team`, `ai_try_to_fight`, `players_on_multiplayer_team <short>`. https://c20.reclaimers.net/h1/scripting/
- H3 / ODST / Reach / H4: `mp_ai_allegiance <team> <mp_team>` "causes an allegiance to be formed between an AI squad team and a multiplayer team"; `mp_allegiance`; `mp_players_by_team <mp_team>`; `ai_set_targeting_group <ai> <short> [<boolean>]` (optional player targeting). https://c20.reclaimers.net/h3/engine/scripting/, https://c20.reclaimers.net/hr/engine/scripting/, https://c20.reclaimers.net/h4/engine/scripting/
- Reach Forge AI mod:; factions team up automatically. Search summary of https://www.nexusmods.com/halothemasterchiefcollection/mods/117

### 4.5 Respawning AI
- All games: `ai_place <squad> [count]` from scripts; `ai_living_count`, `ai_task_count`, `ai_spawn_count` (H4) to detect deaths; H3 adds `mp_ai_place` and `mp_ai_kill`. H4 adds `ai_place_wave`, `ai_place_in_limbo`. https://c20.reclaimers.net/h3/engine/scripting/ , https://c20.reclaimers.net/h4/engine/scripting/
- ODST Firefight is the reference implementation: `global_survival` respawns waves and resets objectives. https://c20.reclaimers.net/h3odst/guides/firefight/firefight-setup/

### 5.2 Script model and limits
- Script types: startup, dormant, continuous, static, command_script (only type allowed to use `cs_` functions and `ai_current_actor`). Threads are cooperative on one core; each thread has its own stack; a sleep in a static script sleeps the caller. Globals only declared in scenario scripts; H4 added local variables. https://c20.reclaimers.net/general/scripting/
- CE limits (HEK vs H1A/MCC): syntax nodes 19001 vs 32767; scripts 512 vs 1024; globals 128 vs 512; source file 256 KB vs 1 MB; source files 8 vs 16 (extra files silently dropped); tag references 256 vs 512; string data 256 KB vs 800 KB; 48 object lists / 128 references; 256 running threads; 1280 byte stack per thread, about 10 to 16 nesting levels, and release builds do not guard against stack overflow into other scripts. Random functions in startup scripts are seeded identically every time. https://c20.reclaimers.net/h1/scripting/limits/
- H1A extras: script parameters (up to 16), bitwise functions, auto-compile of `.hsc` from `data\...\scripts`; `change_team` removed in H1A. https://c20.reclaimers.net/h1/scripting/
- H2+ limits: UNVERIFIED (no c20 limits page found for H2/H3/Reach/H4).
- Self-documentation: H3+ have `(help <function>)`. https://c20.reclaimers.net/h3/engine/scripting/ . The MCC `script_doc` command that writes a full function list: UNVERIFIED (not found in c20 text this pass).

### 5.3 Do scripts run in MP scenarios?

## 8. What a MP map needs before AI can work (checklist)

1. Pathfinding data: CE has it already [1]. H2: regenerate if the BSP or scenery changed; open edges break it [2]. H3/ODST/Reach: sealed level, then Sapien "Generate all pathfinding data" [3]. H4: UNVERIFIED.
2. Hints for MP traversal: jump hints for gaps and drops, climb hints for ledges, cookie cutters for bad junctions, `railing` jump hints for vaults [3]. Teleporters / man cannons / lifts need script workarounds (UNVERIFIED native support).
3. Placement data: CE encounters + squads + lettered firing positions [6]; H3+ zone, areas, firing positions (with corner / bunker flags), squads (one bot per squad recommended), squad groups per team, objectives + tasks per team [3][7].
4. Character + style tags (H3+ both required) [19], AI-capable biped and animation graph (H3 needs a custom Spartan, Reach has `spartans_ai`) [17].
5. Team mapping: `mp_ai_allegiance` (H3+) or encounter team index / `ai_allegiance` (CE) [12][13].
6. Director script: respawn loop with `ai_place` + `ai_living_count`, role assignment with `ai_set_task` / `ai_migrate`, awareness with `ai_magically_see`, objective state from `volume_test_objects` and flag holder checks.
7. Scoring bridge: H4 `adjust_team_score`; Reach Megalo (untested); CE/H3 custom globals + HUD (no native AI score found).

## Hard blockers and open questions

### Hard blockers (likely)
1. **Networked play.** CE AI never syncs (engine design, c20). H2 and H4 MP reportedly cannot network AI at all (modder claim). H3 `mp_ai_*` are "non-authoritative". Only ODST/Reach Firefight have proven networked AI. Plan for local-only (host plus local players) in CE, H2, H3, H4; Reach (and possibly ODST-style Firefight scenarios) is the only realistic online target.
2. **Objective items.** No evidence that AI will pick up, carry, or capture a CTF flag or oddball through the game engine. CTF bots may need a scripted fake (attach object, script capture checks) or memory-level help.
3. **Scoring.** No evidence AI kills count on the MP scoreboard or killfeed in any game. Only H4 has `adjust_team_score` / `adjust_player_score`. Without that, Slayer scores need custom script globals and HUD, or Megalo (Reach), or memory hacks.
4. **AI-ready Spartan bipeds.** H3 stock Spartan has no AI animation set and lacks a `physics_control` node; a custom biped and graph is required. Unknown for H2, H4.
5. **Non-player-like behaviour baked into the engine.** H3-family AI never reload (no ammo use), cannot shoot while jumping, cannot melee while moving, cannot move while throwing grenades, share info only within squad/task. These are hard-coded per c20 and cannot be fixed by tags.
6. **Teleporters / man cannons / lifts.** No documented native AI support; needs script teleport workarounds or zone splitting.
